# Proposal

## Why

Проверенный skill подключения fc/shell пока доступен только как исходники в gost-spec. Владелец хочет устанавливать его в Codex и Claude Code через маркетплейсы, с общей реализацией и независимой версией устанавливаемого плагина.

## What Changes

- Подготовить один самодостаточный плагин `gost-svelte-spa-state` с единственным исходником существующего skill и его API recipe.
- Добавить два нативных каталога Git-маркетплейса в этом репозитории: для Codex и Claude Code; оба доставляют один и тот же skill одной версии.
- Определить независимые version/changelog плагина, проверку согласованности метаданных и воспроизводимую установку выбранной ревизии без связи с версиями пяти пакетов стандартов или gost-kit.
- Проверить фактическую установку, обнаружение skill, доступность references, повторное подключение и обновление в изолированных профилях обоих харнесов.
- Сохранить границы skill: установка плагина сама не подключает fc/shell к приложению и не мигрирует бизнес-фичи.

## Capabilities

### New Capabilities

- `state-foundation-plugin-distribution`: доставка и независимое версионирование одного плагина fc/shell через маркетплейсы Codex и Claude Code.

### Modified Capabilities

Нет. Требования `svelte-spa-state-foundation` сохраняются; меняются упаковка и способ доставки, а не поведение подключения приложения.

## Impact

Планирование и последующая отдельно запускаемая реализация — [#55](https://github.com/antonsmolko/gost-spec/issues/55), исходный skill — [#54](https://github.com/antonsmolko/gost-spec/issues/54). Владелец выбрал общий репозиторий и два каталога; scope первого плагина ограничен существующим skill.

Будущая реализация затронет размещение skill, метаданные плагина, два каталога, узкое исключение `.gitignore`, проверки и ссылки документации. Пять npm workspaces и их версии сохраняются. Собственный installer, npm-пакет плагина, новые MCP-серверы, официальные каталоги вендоров, публикация, создание release tags и применение к asc-admin не входят в этот change.

Carrier-ветка — `feature/gost-spec-54-state-foundation-skill`, retained prefix `[gost-spec-52]` по указанию владельца. Новый outcome не расширяет criteria/closure #54; его implementation PR должен быть отделён от предыдущих outcomes. Текущие staged archives сохраняются отдельно. Нынешнее подтверждение разрешает подготовку плановых артефактов; реализация требует нового apply-запроса.
